Making Gradient Descent Fast

By Shikha Pallavi

▶ Run the code for this part

The algorithm from Part 3 can finish in seconds or in milliseconds. The math is identical. What changes is how you write it. Here are three versions, a correctness check, and real measurements.

loopnumpymatrixmeasure

One update, three ways

Every version repeats the same two lines of math: nudge θ0 and θ1 against the average error.

A · Python loop
for step in range(steps):
    g0 = g1 = 0.0
    for i in range(n):              # one sample at a time
        err = t0 + t1*x[i] - y[i]
        g0 += err
        g1 += err * x[i]
    t0 -= alpha * g0 / n
    t1 -= alpha * g1 / n
B · NumPy
for step in range(steps):
    err = t0 + t1*x - y             # whole array at once
    t0 -= alpha * err.mean()
    t1 -= alpha * (err * x).mean()
C · Matrix form
X = np.column_stack([np.ones(n), x])
for step in range(steps):
    theta -= alpha * (X.T @ (X @ theta - y)) / n

Stack a column of ones next to x and the whole gradient is one line, Xᵀ(Xθ − y) / n. It also works unchanged with many features.

Check it first

A fast wrong answer is useless. On the same 2,000 points, all three versions land on exactly the same parameters:

θ0 = 4.001178   θ1 = 2.997182

The data was generated from θ0 = 4 and θ1 = 3 plus a little noise, so this is what we expect.

The race

Pick a data size and start the race. Bar length shows time for 200 steps, relative to the slowest version at that size.

 

Measured in a notebook run on a 2-core cloud machine: 200 steps, best of a few runs. Your numbers will differ, the pattern should not. The pure Python loop is not run at 1,000,000 samples because it takes too long to wait for.

Why the gap?

Interpreter overhead

Each x[i], multiply and add in a Python loop passes through the interpreter, which does extra work on every one.

Compiled inner loops

NumPy runs the same arithmetic in compiled code over a contiguous block of memory, often with the CPU’s vector instructions.

One operation, same story

Summing the squares of 1,000,000 numbers took 86.1 ms in a Python loop and 1.53 ms with NumPy in the same notebook run.

One honest detail from the table: the matrix form was not always faster than plain NumPy. At 100,000 samples B won; at 1,000,000 samples C won. Which is faster depends on size and hardware, which is exactly why you measure.

Profile, don’t guess

Before optimizing anything, ask the profiler where the time goes. Python ships with one:

import cProfile, pstats
pr = cProfile.Profile(); pr.enable()
gd_numpy(x, y, steps=50)
pr.disable()
pstats.Stats(pr).sort_stats("cumulative").print_stats(6)

The notebook runs this and shows the result, so you can see which lines dominate before you change a thing.
